opengrid — the engine in a Web Worker

The same interface as the grid demo, but the engine runs in a Web Worker (createWorkerProvider): the main thread keeps the DOM, the events and the rendering, while the worker takes ingest, filtering, sorting and grouping. The counter 0 counts requestAnimationFrame frames, and it keeps climbing during a large query — which is the point. Fully keyboard-operable under the WAI-ARIA grid pattern, with the same filter row above the table.

Generate the 100k data set (optional)

The 100k data set is not checked in. Without it the demo falls back to the small conformance data set. To generate it, from the repository root: 

mkdir -p target/worker-demo
cargo run -p xtask -- gen-orders --rows 100000 --seed 1 --out target/worker-demo/orders-100k.csv
just wasm-build            # engine module
just wasm-build-components # element module
just serve-demo            # then open http://127.0.0.1:8080/examples/worker-demo/

The query's columns (id,customer,country,amount,qty) are a subset of the ten-column schema xtask generates. The default sort key is the first column (id, ascending), because paging needs a total order (rule S6).
